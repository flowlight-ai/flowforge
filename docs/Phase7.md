### 1.1 域名注册与品牌保护（总耗时约4小时）

我将以**域名策略师**的身份来指导。域名是你的数字门牌号，一旦选错，后期的迁移成本极高。

#### 1.1.1 注册策略

| 策略 | 具体做法 | 预算 |
|------|---------|------|
| **首选** | 主攻 `flowforge.ai`、`openroute.ai`、`opensieve.ai`，`.ai`后缀对AI项目有强烈的行业信号价值 | ~$80-100/年/个 |
| **备用** | 如首选被占，立刻切换 `flowforge.dev`、`openroute.dev`、`opensieve.io` 等 | ~$12-20/年/个 |
| **防御** | 将备选域名一并注册，设置301跳转到主域名，防止竞争对手抢注 | ~$50-100/年 |

#### 1.1.2 分步操作清单

| 步骤 | 操作 | 工具/平台 | 耗时 |
|------|------|----------|------|
| **Step 1：批量查询** | 打开浏览器，用3个标签页分别查询首选域名的Whois信息 | [whois.com](https://www.whois.com) 或命令行 `whois flowforge.ai` | 10分钟 |
| **Step 2：注册平台** | 对比**Namecheap**、**GoDaddy**、**Porkbun**三家平台，选有新人优惠的 | [namecheap.com](https://www.namecheap.com) / [godaddy.com](https://www.godaddy.com) / [porkbun.com](https://www.porkbun.com) | 30分钟 |
| **Step 3：购物车结账** | 将可用的首选域名和1-2个防御域名同时加入购物车，**开启自动续费** | 注册商购物车 | 15分钟 |
| **Step 4：Whois隐私保护** | 确认注册商提供的**Whois隐私保护服务**已开启（主流平台免费提供），隐藏个人真实信息 | 注册商设置页 | 5分钟 |
| **Step 5：DNS解析配置** | 将域名默认DNS修改为 **Cloudflare**（后文会详述），利用其全球CDN、免费SSL、DDoS防护等能力 | Cloudflare控制台 | 30分钟 |
| **Step 6：企业邮箱设置** | 在Cloudflare中设置邮件路由，将 `hello@flowforge.ai` 转发到团队Gmail，不花钱拥有企业级邮箱 | Cloudflare → Email Routing | 20分钟 |

**🔴 真实大坑预警**：
- **.ai域名锁定期**：部分注册商购买后60天内禁止转移，中途想转平台很麻烦，所以**首次选平台一定要慎重**。
- **备案与服务器的隐藏关联**：将域名解析到中国大陆服务器，**必须先完成ICP备案**，否则会被云厂商拦截访问。短期先指向境外服务器或使用Cloudflare的代理模式（橙色云朵），等公司完成备案后再切换。
- **遗忘续费**：域名每年都会过期，**务必开启自动续费，并绑定常用信用卡**，否则域名会被高价赎回。

### 1.2 GitHub开源项目搭建（总耗时约8小时）

我以**开源项目架构师**的身份来指导。GitHub不只是代码仓库，更是你开源项目的门面、文档中心和社区聚集地。

#### 1.2.1 组织与仓库设定

| 任务 | 具体操作 | 耗时 |
|------|---------|------|
| **创建组织** | 登录GitHub → 右上角"+" → "New Organization" → 选择"Free"计划 → 组织名填 `flowforge` | 15分钟 |
| **设置组织资料** | 上传Logo（用AI生成或Canva制作）、填写组织简介（"We build open-source AI infrastructure: Agent orchestration, Model routing, Retrieval augmentation."）、添加官网链接、邮箱、Twitter | 30分钟 |
| **创建三个公开仓库** | 分别创建 `flowforge`（核心编排引擎）、`openroute`（模型网关）、`opensieve`（检索增强），三个仓库 **必须选择"Public"** ，不要勾选"Add a README file"（后面手动添加更精细） | 15分钟 |
| **启用GitHub Discussions** | 每个仓库的 Settings → General → Features → 勾选"Discussions"，用于社区问答 | 5分钟 |
| **设置分支保护** | Settings → Branches → Add rule → `main`分支 → 勾选"Require a pull request before merging" | 10分钟 |

#### 1.2.2 安全配置（关键，不可跳过）

| 任务 | 具体操作 | 工具 |
|------|---------|------|
| **开启2FA** | GitHub要求所有贡献者必须开启双因素认证，否则无法操作组织仓库 | GitHub Settings → Password and authentication |
| **禁用机密扫描（Push Protection）** | Settings → Code security → "Push protection" → 勾选"Prevent contributors from pushing secrets"。防止API Key被不小心推到公开仓库 | GitHub内置 |
| **添加.gitignore** | 项目根目录创建 `.gitignore`，填入 `.env`、`node_modules/`、`__pycache__/`、`*.db`、`.venv/` | - |

**🔴 真实大坑预警**：
- **密钥泄露是开源项目最常见的灾难**：每天都有开发者的云服务Key在GitHub上被扫描并被盗用。你的OpenRoute将管理大量模型API Key，**务必在第一天就打开Push Protection**。

### 2.2 税务与银行：同步变更，保障经营血脉（第12-20天）

拿到新营业执照后，需立即办理税务和银行信息同步。

**📌 税务变更**

| 条件 | 具体要求 |
| :--- | :--- |
| **办理渠道** | 线上登录本省“电子税务局”；线下前往主管税务机关办税服务厅。 |
| **核心目的** | 将公司名称、经营范围、税种核定等信息与工商信息同步。 |
| **必办事项** | 1. 变更税务登记信息（公司名称等）。 2. 重新核定税种（特别是经营范围变更后）。 3. 变更发票票种核定信息（公司名称变更后，发票抬头须更新）。 |

### 3.1 基础环境配置（第10-11天）

| 组件 | 安装命令/方式 |
| :--- | :--- |
| Docker | `curl -fsSL https://get.docker.com \| sudo sh` |
| Docker Compose | `sudo apt install docker-compose-plugin` |
| Git | `sudo apt install git -y` |
| UFW防火墙 | `sudo apt install ufw -y` |

**⚠️ 下列操作仅供参考，请根据你的实际环境和偏好进行调整，尤其是网络配置和安装命令可能因系统版本而异。**

**Docker安全基线加固**

| 序号 | 检查项 | 配置方法 |
| :--- | :--- | :--- |
| 1 | Docker Daemon仅监听本地socket | 编辑 `/etc/docker/daemon.json`，设置 `{"icc": false, "userns-remap": "default"}`。`icc: false` 禁止容器间通信，`userns-remap` 开启用户命名空间映射，将容器内root映射为宿主机非特权用户。 |
| 2 | 启用用户命名空间隔离 | 同上，`"userns-remap": "default"`。这会自动创建 `dockremap` 用户并将容器root映射为其子UID，有效防止容器逃逸后获得宿主机root权限。 |
| 3 | 限制容器资源 | 在Docker Compose文件中为每个服务配置CPU与内存上限。 |
| 4 | 定期扫描镜像漏洞 | 使用 `docker scout` 或 Trivy 进行定期扫描。 |

> ⚠️ 关于使用 Docker Compose 的说明：虽然 Kubernetes 是行业标准，但对于 1-2 人的早期创业团队而言，其学习和运维成本偏高，容易拖慢迭代速度。使用 Docker Compose 可以快速部署，后续业务扩大时再考虑迁移到轻量级 K3s。

**UFW防火墙配置**

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp   # SSH
sudo ufw allow 80/tcp   # HTTP
sudo ufw allow 443/tcp  # HTTPS
sudo ufw enable
```

**🔴 大坑预警**：

| 序号 | 风险点 | 具体危害 | 预防/解决方法 |
| :--- | :--- | :--- | :--- |
| 1 | **数据盘未挂载** | 若购买了额外数据盘（如100GB SSD），但未格式化挂载，则所有数据仍写满40GB系统盘，导致服务中断。 | 购买后在云商控制台查看数据盘设备名（如 `/dev/vdb`），使用 `fdisk` 格式化，`mount` 挂载到 `/data` 目录，并写入 `/etc/fstab` 实现开机自动挂载。 |
| 2 | **安全组端口未放行** | 部署完成后外部完全无法访问，这是新手最常见的故障原因。 | 在云商安全组规则中放行 `80/443/22` 端口。确认云商有两个防火墙：**安全组**（云商控制台配置）和**操作系统防火墙**（UFW/iptables），两者是独立生效的，必须都放行端口。 |
| 3 | **时钟不同步** | 容器与宿主机时间不一致，TLS证书验证失败或API签名报错，极难排查。 | 启用 `systemd-timesyncd` 或安装 `chrony` 配置NTP自动同步。 |
| 4 | **OOM Killer导致随机崩溃** | 内存不足时内核随机杀进程，现象诡异且不可预测。 | 为Docker服务硬性配置 `mem_limit`，并为宿主机配置Swap（推荐4GB），预留内存缓冲。 |

### 3.3 Nginx反向代理与SSL配置（第14-15天）

| 序号 | 配置要点 | 详细说明 |
| :--- | :--- | :--- |
| 1 | **WebSocket支持** | FlowForge的工作流编辑器需要实时推送状态，Nginx默认不支持WebSocket协议升级，必须增加 `Upgrade` 和 `Connection` 头配置。 |
| 2 | **API速率限制** | 用 `limit_req_zone` 和 `limit_req` 指令限制OpenRoute API的调用频率，防止滥用和DDoS。 |
| 3 | **自动HTTP→HTTPS跳转** | 所有HTTP流量强制重定向到HTTPS。 |
| 4 | **SSL会话缓存** | 开启 `ssl_session_cache` 减少TLS握手开销，提升响应速度。 |

**WebSocket关键配置**（若缺少此项，工作流编辑器将无法正常使用）：

```nginx
location /ws {
    proxy_pass http://flowforge-web:3000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 86400s;    # 长连接必须加长超时
}
```

#### 3.3.1 SSL证书申请与自动续期

Let's Encrypt免费SSL证书，有效期90天，需设置自动续期。

| 步骤 | 操作 |
| :--- | :--- |
| 1. 安装certbot | `sudo apt install certbot python3-certbot-nginx -y` |
| 2. 申请证书 | `sudo certbot --nginx -d flowforge.ai -d www.flowforge.ai` |
| 3. 测试自动续期 | `sudo certbot renew --dry-run` |

**🔴 大坑预警**：certbot申请的Let's Encrypt证书有效期仅90天。certbot默认会在证书到期前30天自动尝试续期，但若服务器在续期时间点恰好关机/网络不通/防火墙拦截了80端口，续期会失败，导致用户在证书过期后访问网站看到"不安全"警告。务必通过cron或systemd timer确保续期任务正常运行，并设置邮件告警。


### 3.4 CI/CD流水线搭建（第15-16天）

使用GitHub Actions实现代码推送后自动构建Docker镜像并部署到服务器。

| 序号 | 配置要点 | 详细说明 |
| :--- | :--- | :--- |
| 1 | **多阶段构建** | Dockerfile使用多阶段构建，将编译环境和运行环境分离，最终镜像仅包含运行时依赖。 |
| 2 | **密钥管理** | API Key等敏感信息存储在 **GitHub Secrets** 中，绝不写入代码或配置文件。 |
| 3 | **镜像标签策略** | 同时打 `latest` 和 `git-sha` 两个标签，方便回滚时指定具体版本。 |
| 4 | **部署前健康检查** | 部署脚本中包含 `curl` 检查新容器是否真正启动成功，失败则自动回滚。 |

**GitHub Actions关键步骤**

```yaml
# .github/workflows/deploy.yml (关键片段)
env:
  REGISTRY: ghcr.io
  IMAGE_NAME: ${{ github.repository }}

steps:
  - name: Build and push Docker image
    uses: docker/build-push-action@v5
    with:
      push: true
      tags: ${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}:latest,${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}:${{ github.sha }}
      cache-from: type=gha       # 利用GitHub Actions缓存加速构建
      cache-to: type=gha,mode=max

  - name: Deploy to production server
    uses: appleboy/ssh-action@v1
    with:
      host: ${{ secrets.SERVER_HOST }}
      username: ${{ secrets.SERVER_USER }}
      key: ${{ secrets.SERVER_SSH_KEY }}
      script: |
        cd /opt/flowforge
        docker compose pull
        docker compose up -d --remove-orphans
        docker image prune -f   # 清理旧镜像，释放磁盘空间
```

**🔴 大坑预警**：随着部署次数的增加，服务器上的旧Docker镜像会大量堆积，迅速耗尽磁盘空间（100GB SSD可能几周就被占满）。务必在CI/CD部署脚本中添加 `docker image prune -f` 清理72小时外的未使用镜像，配合 cron 每周执行一次 `docker system prune -a` 清理所有无用数据。


### 3.5 监控与告警系统搭建（第16-18天）

部署完整的Prometheus + Grafana监控栈。

| 序号 | 监控对象 | 关键指标 | 告警规则 |
| :--- | :--- | :--- | :--- |
| 1 | 服务器基础资源 | CPU使用率、内存使用率、磁盘空间、网络流量 | CPU > 80%持续5分钟或磁盘 > 85%，钉钉/飞书通知 |
| 2 | Docker容器状态 | 各容器运行状态、重启次数、资源占用 | 容器退出（exit code ≠ 0）或重启次数 > 3 |
| 3 | OpenRoute API | 请求量、延迟（P50/P95/P99）、错误率、Token消耗 | API错误率 > 5%或P95延迟 > 2000ms |
| 4 | SSL证书 | 证书到期时间 | 剩余 < 20天提醒，< 7天紧急告警 |

**告警通知渠道**：钉钉/飞书机器人 Webhook、邮件。这两个渠道是创业公司最常用的即时通知方式，实现简单且免费。

**🔴 大坑预警**：告警太多等于没有告警。如果你设置CPU > 50%就告警，每天会收到大量无意义通知，最终你会关闭告警渠道。建议P0告警仅设置3类：**服务宕机、磁盘 > 90%、API错误率飙升**，其他指标仅做Grafana大盘展示，用于事后分析。
