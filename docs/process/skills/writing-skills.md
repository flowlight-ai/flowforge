# 编写技能（writing-skills）

## 触发时机

- 创建新的流程指令资产（`docs/process/skills/` 下新文件）。
- 编辑既有资产。
- 部署前验证资产确实生效。

**核心思想**：编写技能 = 把测试驱动开发应用于流程文档。写测试用例（带子代理的压力场景）→ 看它失败（基线行为）→ 写技能（文档）→ 看测试过（子代理合规）→ 重构（堵漏洞）。

**核心原则**：没见过子代理在没有该资产时失败，你不知道这个资产教的是不是对的东西。

## 流程步骤

### 何时该建/不该建

**建**：技巧不是显而易见的、以后会跨项目复用、模式适用面广、他人受益。
**不建**：一次性方案、他处已有良好文档的标准实践、项目专属约定（放进项目规范文件）、能用正则/校验自动化的机械约束（自动化它，文档留给判断类问题）。

### TDD 映射

| TDD 概念 | 技能创建 |
|---|---|
| 测试用例 | 带子代理的压力场景 |
| 生产代码 | 资产文档（SKILL 结构正文） |
| 测试失败（RED） | 无资产时子代理违规（基线） |
| 测试通过（GREEN） | 有资产时子代理合规 |
| 重构 | 堵新出现的合理化漏洞 |
| 先写测试 | 写资产**前**先跑基线场景 |
| 看它失败 | 记录子代理违规时用的确切合理化措辞 |
| 最小实现 | 只针对那些具体违规写资产 |
| 看它通过 | 验证子代理现在合规 |

### 目录与结构约定

本仓库流程资产为单文件平面结构（`docs/process/skills/<名称>.md`），每个文件必含四节：**触发时机 / 流程步骤 / 门禁 / 与我方规范对接**；frontmatter 含 `name`/`description`/`phase`/`source`。

重内容（100+ 行参考）才拆支撑文件；代码模式（< 50 行）内联。

### 验证循环

1. **基线**：无资产时跑压力场景，记录子代理的违规与合理化措辞。
2. **写资产**：针对那些具体违规写内容（含"典型自我合理化对照表"——每张表来自真实的基线观察）。
3. **复验**：有资产时重跑场景，确认合规。
4. **重构**：发现新合理化路径 → 补条目 → 再验。

## 门禁

- **没跑基线就写资产** = 没见过失败就写测试：你不知道资产教的对不对。
- **资产写的是叙事**（"我是怎么解决那次问题的"）而非可复用技术 = 不合格：技能是参考指南，不是故事。
- **机械约束进文档** = 不合格：能自动化的用代码校验（如 EP0-2 的 No-Placeholder 校验器），文档留给判断类问题。
- **新资产必须过四节结构**：触发时机/流程步骤/门禁/与我方规范对接缺一即退回。

## 与我方规范对接

- **元方法论定位**：本资产服务流程资产自身的迭代——`docs/process/skills/` 里任何一份资产的增改都应走这里的 TDD 循环。
- **Plane 1/Plane 2 分工**：资产（文档）教判断，插件（代码）管强制——机械化校验优先下沉到 Plane 2（如计划校验器），文档聚焦方法与门禁语义。
- **术语**：新资产用语遵循命名契约；涉及智能体区分静态/可进化。
- **压力场景**：使用 flowforge 子代理体系（`packages/subagent/*`）跑基线与复验。
- **文档规范**：正文遵循本仓库文档规范（中文、官方术语优先、不超 1000 行/文件的可维护性约束）。
