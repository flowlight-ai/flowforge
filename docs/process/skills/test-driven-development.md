# 测试驱动开发（test-driven-development）

## 触发时机

- **永远**适用于：新功能、缺陷修复、重构、行为变更。
- **豁免（需操作者同意）**：一次性原型、生成代码、纯配置文件。
- 念头"就这次跳过 TDD"？停——那是自我合理化。

## 流程步骤

### 铁律

```
没有先失败的测试，就没有生产代码
```

先写了代码再补测试？删掉代码，重来。删除意味着删除——不留"参考"、不"边看边改写测试"、不偷瞄。从测试出发重新实现。

### RED-GREEN-REFACTOR 循环

**RED — 写失败测试**：一个最小测试表达一个行为；命名清晰（描述行为，不是 `test1`）；测真实代码，不测 mock。

**验证 RED — 看它失败（强制，永不跳过）**：跑 `pnpm vitest run <测试路径>`，确认：失败（不是报错）、失败信息符合预期、失败原因是特性缺失（不是笔误）。测试直接通过 = 在测既有行为，修测试；报错 = 先修到"正确地失败"。

**GREEN — 最小实现**：只写让测试通过的最简代码；不加特性、不顺手重构、不做超出测试的"改进"。

**验证 GREEN — 看它通过（强制）**：目标测试过、其他测试不破、输出干净（无错误无警告）。失败 → 修代码不修测试；其他测试破 → 立即修。

**REFACTOR — 清理**：仅在绿色之后；去重复、改命名、提取辅助；保持绿色、不加行为。

### 缺陷修复集成

发现 bug → 先写复现该 bug 的失败测试 → 走循环。**绝不修没有测试的 bug**——测试既证明修复又防回归。

## 门禁

完成前自查清单（做不到 = 跳了 TDD，重来）：

- [ ] 每个新函数/方法有测试
- [ ] 每个测试都先看到失败
- [ ] 每个测试因预期原因失败（特性缺失，不是笔误）
- [ ] 每个实现都是最小的
- [ ] 全部测试通过
- [ ] 输出干净（无错误、无警告）
- [ ] 测试用真实代码（mock 仅在不可避免时）
- [ ] 边界与错误路径有覆盖

典型自我合理化对照（节选）：

| 借口 | 事实 |
|---|---|
| "太简单不用测" | 简单代码也会坏；测试只要 30 秒 |
| "回头补测试效果一样" | 后补的测试立即通过——什么都没证明；先写测试才逼你看见它失败 |
| "手动测过了" | 手动测试无记录、不可重放、换代码就失效 |
| "删掉 X 小时的工作太浪费" | 沉没成本谬误；留着自己不信的代码才是浪费 |
| "测试难写 = 继续硬写" | 测试难写 = 设计难用；听测试的，简化接口 |

## 与我方规范对接

- **T1-T9 裁决（关键）**：本资产与测试铁律（`docs/refactor/04-code-standards.md` §2.2）冲突时，**以 T1-T9 为最高裁决**。典型裁决点：
  - 本资产允许"mock 在不可避免时使用"，但 **T1 禁止 Mock LLM、T4 禁止 Mock 工具**——E2E/集成测试一律真实调用，单测中注入的也只是协议替身而非 LLM mock；
  - 本资产要求"看它失败"，与 **T3 必须有具体断言** 叠加：失败还必须失败在断言上；
  - **T2 禁止假数据**：RED 阶段的测试输入也必须是真实场景数据，不是编造的 `"test"` 字符串。
- **对应状态机**：本资产在 `plan → implement` 门禁的机器化中体现为"每个任务必须含测试步骤"（planValidated 的校验项之一）。
- **测试命令**：flowforge 统一 `pnpm vitest run <路径>`；类型检查 `pnpm typecheck` 不替代测试。
- **审查对接**：任务审查者以本资产清单为评分依据；缺"先失败"证据的测试判 Important 缺陷（见 ⑦⑧）。
