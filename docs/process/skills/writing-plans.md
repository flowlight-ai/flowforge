# 编写实施计划（writing-plans）

## 触发时机

- 已有规格（`docs/process/specs/` 中的设计文档）或明确需求，任务是**多步**的。
- 在触碰任何代码之前。
- 开始时宣布："正在使用 writing-plans 资产编写实施计划。"

## 流程步骤

### 1. 范围检查

规格覆盖多个独立子系统时，应已在头脑风暴阶段分解；若没有，建议按子系统拆成多份计划——每份计划独立产出可运行、可测试的软件。

### 2. 文件结构先行

定义任务前先映射将创建/修改哪些文件、各管什么：
- 单一职责、边界清晰、接口明确；偏小而聚焦的文件。
- 一起变更的文件放一起；按职责拆，不按技术分层拆。
- 存量代码库遵循既有模式；不单方面重构（但被修改的文件确实失控时可把拆分纳入计划）。

### 3. 任务切分（bite-sized）

- **任务**是最小可独立测试、值得一个独立审查门的单元；搭建/配置/脚手架/文档步骤折进需要它的任务，只在"审查者可能通过 A 拒绝 B"处切分。
- **步骤**是 2-5 分钟的单个动作：写失败测试 → 跑一遍确认失败 → 写最小实现 → 跑一遍确认通过 → 提交。

### 4. 计划文档头（每份计划必含）

```markdown
# [特性名] 实施计划

> **执行者必读**：使用 subagent-driven-development（④，推荐）或
> executing-plans（③）逐任务执行本计划。步骤使用 checkbox（`- [ ]`）跟踪。

**目标**：[一句话]
**架构**：[2-3 句]
**技术栈**：[关键技术]
**规格**：[本计划实现的规格路径——计划从规格出发，执行者两者都读]

## 全局约束

[规格的项目级要求——版本下限、依赖限制、命名与文案规则、平台要求——逐条列出，精确值从规格原文照抄。每个任务隐式继承本节。]
```

### 5. 任务结构（每个任务必含）

```markdown
### 任务 N：[组件名]

**文件**：
- 新建：`精确/路径/文件.ts`
- 修改：`精确/路径/现有.ts:123-145`
- 测试：`tests/精确/路径/测试.ts`

**接口**：
- 消费：[来自早前任务的内容——精确签名]
- 产出：[后续任务依赖的内容——精确函数名、参数与返回类型]

- [ ] **步骤 1：写失败测试**
（完整测试代码）
- [ ] **步骤 2：运行测试确认失败**
（命令 + 预期失败信息）
- [ ] **步骤 3：写最小实现**
（完整实现代码）
- [ ] **步骤 4：运行测试确认通过**
（命令 + 预期通过）
- [ ] **步骤 5：提交**
（mgr 提交命令与规范 commit 消息）
```

### 6. 自审

写完后以新鲜视角检查三项：**规格覆盖**（规格每节能指到对应任务）、**占位符扫描**（见下）、**类型一致性**（任务 N 定义的签名与任务 M 引用的一致——`clearLayers()` vs `clearFullLayers()` 是 bug）。发现问题就地修复。

### 7. 执行交接

计划落盘后向操作者提供两个选项：**子代理驱动（推荐）** 或 **行内执行**，等待选择。

## 门禁

**No Placeholders 铁律**——每一步必须包含执行者需要的真实内容，以下写法均为**计划失败**：

- "TBD"、"TODO"、"以后实现"、"细节略"
- "加上适当的错误处理"/"处理边界情况"（无具体内容）
- "为上述写测试"（无真实测试代码）
- "同任务 N"（必须重复代码——执行者可能乱序读任务）
- 描述做什么但不给怎么做（代码步骤必须带代码块）
- 引用任何任务中未定义的类型、函数、方法

## 与我方规范对接

- **对应状态机**：本资产覆盖 `plan` 阶段；`plan → implement` 门禁（planValidated）的机器化校验即扫描本节"门禁"所列占位符模式 + 检查任务是否含测试步骤（EP0-2 No-Placeholder 校验器）。
- **产物落点**：`docs/process/plans/YYYY-MM-DD-<feature>.md`（EP0-2 启用模板）。
- **提交规范**：步骤中的提交一律走 mgr 命令（`docs/mgr/`），commit 消息遵循 git-workflow 规范（类型前缀 + 署名），禁止直接 push main/master。
- **测试规范**：测试步骤设计与测试铁律 T1-T9 对齐——测试输入为真实场景数据（T2）、断言具体（T3）、禁 Mock LLM（T1）。
- **TDD 绑定**：每个任务的步骤模板已内嵌 RED→GREEN 循环，与 `test-driven-development.md`（⑥）联动。
