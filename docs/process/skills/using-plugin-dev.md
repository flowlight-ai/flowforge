# 流程插件入口（using-plugin-dev）

## 触发时机

- **任何一次需求交付会话开始时**（无论文档交付还是代码交付），在做出任何响应之前——包括澄清提问、探索代码库、查看文件之前。
- 不确定当前任务处于七阶段中的哪一个时。
- 子代理（subagent）被派发去执行特定任务时**不需要**读本资产（子代理只执行派发单内任务）。

## 流程步骤

1. **确认阶段**：判断当前任务处于 `requirement → design → plan → implement → review → verify → finish` 中的哪一阶段（依据：已有产物在 `docs/process/{specs,plans,reviews,verifications}/` 的哪个目录、`@flowforge/plugin-dev` 状态机的实例状态）。
2. **宣布**："当前处于 `<阶段>` 阶段，使用 `<对应资产>` 推进。"（对应关系见 `docs/process/README.md` §4 映射表）
3. **通读该阶段的主资产与辅助资产**，按其流程步骤执行；资产含 checklist 的，为每一项建立 todo。
4. **跨阶段推进前**，对照 README §2 三道硬门禁自查；未过门禁则停在当前阶段补齐。
5. **规范优先级裁决**：本目录资产与操作者直接指令、我方规范（`docs/rules/`、mgr git 流程、测试铁律 T1-T9）冲突时，按 **操作者指令 > 我方规范 > 本目录资产** 的顺序裁决。

## 门禁

- **1% 规则**：只要有 1% 的可能某个流程指令资产适用于当前任务，就必须先读它再动手。以下是典型的自我合理化（rationalization）信号，出现即停：

| 念头 | 事实 |
|---|---|
| "这只是个简单问题" | 问题也是任务，先查资产 |
| "我得先看下代码库" | 资产告诉你**怎么**看，先读资产 |
| "这个资产我记住了" | 资产会迭代，读当前版本 |
| "这个任务不需要正式流程" | 只要资产存在就适用，简单任务会变复杂 |
| "流程优先，用户指令靠边" | 操作者指令永远高于资产；只有操作者明确豁免才可跳过 |

- **先读后动**：在宣布使用某资产之前不进行任何实质性动作（包括澄清提问）。

## 与我方规范对接

- **状态机**：本资产是 `@flowforge/plugin-dev` 七阶段状态机（`packages/plugins/dev/src/state-machine.ts`）的文档面入口；Plane 2 插件将把"确认阶段/门禁自查"自动化为 `forgeProcess` 服务。
- **规范优先级**：与 `docs/refactor/04-code-standards.md` 的三方规范合并（我方规范 P0 → dsh P1 → clowder P2）一致，本资产位于最底层，不得对抗上层规范。
- **术语**：遵循 `docs/design/naming-contract.md`（官方 AI 概念名优先，"灵智"系列别名仅社交场景）。
