# 子代理驱动开发（subagent-driven-development）

## 触发时机

- 有实施计划，且任务间基本独立、可在当前会话内执行。
- 宿主环境具备子代理派发能力（flowforge 的 `packages/subagent/*` 体系；其他 AI 工具的等价子代理机制）。
- 每任务派发一个全新子代理实现 → 任务级审查（规格符合性 + 代码质量）→ 末尾一次全分支广度审查。

**核心原则**：全新子代理 + 任务级审查 + 末端广度审查 = 高质量 + 快迭代。子代理**永不继承**会话上下文——你精确构造它需要的东西。

## 流程步骤

### 准备

1. 隔离工作区（`using-git-worktrees.md` ⑪）；禁止未经操作者同意在 main/master 上实施。
2. **台账（ledger）**：为计划建立 git 忽略的台账目录（`<repo-root>/.process/sdd/<plan名>/`），首行写 `# SDD 台账 — 计划：<计划文件路径>`。会话记忆活不过压缩，台账才是恢复点：已完成任务不重派。
3. 通读计划一次，记录全局约束；规格（spec）是权威，计划是论证——计划内部冲突以规格裁决。
4. **派发前扫描**：通读计划找冲突（互相矛盾的任务、与全局约束冲突、审查评分标准会判为缺陷的强制项），逐条记入台账并先行裁决。

### 任务循环（每任务）

1. **派发实现者**：记录 BASE commit → 用任务简报（仅该任务的完整文本，不是整份计划）派发；派发单含：任务定位一句话、简报路径、早前任务的接口约定、你对歧义的裁决、报告文件路径。实现者禁止再派子代理。
2. **处理报告**：DONE → 生成审查包派发任务审查者；DONE_WITH_CONCERNS → 先读担忧再定；NEEDS_CONTEXT → 补上下文重派；BLOCKED → 按原因处理（补上下文/换更强模型/拆小任务/裁决计划错误）。
3. **任务级审查**：审查者拿三样东西——任务简报、实现者报告、diff 审查包（commit 列表 + stat + 全量 diff，落成文件不进你上下文）；同时给全局约束原文。双裁决缺一不可：**规格符合性** 与 **任务质量**。
4. **修复循环（最多 5 轮）**：审查报规格❌或 Critical/Important → 派修复。轮 1-3 复用原实现者；轮 4-5 换更强模型的新实现者。每轮收窄范围复审（只验证旧发现是否 ADDRESSED + 修复 diff 是否引入新破坏）。Minor 发现记台账延后，不进循环；与计划文本冲突的发现由你裁决并记台账。
5. **第 5 轮熔断**：停止派发，逐条裁决——审查者错了/可争议 → 停放（parked）+ 裁决理由；真实但无下游依赖 → 停放 + 延后；真实且承重 → 最小改动裁决 + 记台账 + 带入下一任务派发单。
6. **完成记账**：`任务 N：完成（commits a1b2c3d..d4e5f6a，审查干净）`。

### 全分支终审

- 全部任务后派发终审（最强模型），给全分支 diff 审查包 + 台账中所有停放/延后条目做合并前分诊。
- 终审有发现 → **一次性**派单个修复子代理（不是每个发现一个），一次收窄复审，残余按熔断规则裁决。没有第二波修复。

### 收尾

- 删除本计划工作区前，把台账中所有 `裁决：` 行汇总进最终消息（"我做过的裁决"清单，每条含"错了的代价"）——这是你代操作者做的决策唯一送达他们的地方。
- 终审干净后删除工作区（git 历史即记录），转 `finishing-a-development-branch.md`（⑫）。

## 门禁

- **控制器不亲自修代码**：你的上下文要保持干净用于协调；控制器修复绕过审查。
- **修复必须复审**：跳过复审的修复就是回归的入口。
- **裁决必须入台账**：静默丢弃发现是被禁止的；只在第 5 轮熔断时裁决，提前裁决就是换个名字的预判。
- **连续执行**：任务间不停下来问"要继续吗"；只有四类事能停：不可逆/破坏性操作、安全敏感动作、工作区外的副作用（merge/push 共享分支/发布）、计划烂到每条路都是猜。

典型自我合理化对照：

| 念头 | 事实 |
|---|---|
| "规格差不多符合了" | 审查者发现规格缺口 = 没完成；修复或熔断裁决，只有这两个出口 |
| "我自己修更快" | 控制器修复污染上下文且绕过审查；复用实现者 |
| "修复很小，跳过复审" | 未复审的修复是回归的入口；每轮都以收窄复审收尾 |
| "台账是开销" | 台账活过上下文压缩；没有台账的控制器重派过整个已完成的任务序列 |

## 与我方规范对接

- **对应状态机**：本资产覆盖 `implement` 阶段；EP0-4 将以 `packages/subagent/subagent-ff-sdk` 编排实现 Plane 2 自动化。
- **模型分级**：机械任务用廉价模型、集成任务用标准模型、架构/终审用最强模型；flowforge 子代理体系支持按任务指定模型。
- **提交规范**：子代理的提交走 mgr；commit 消息含任务标识，便于台账回溯。
- **审查对接**：任务级审查与 `requesting-code-review.md`（⑦）模板复用；P1/P2/P3 分级响应见 `receiving-code-review.md`（⑧）。
- **T1-T9**：审查者以测试铁律为评分底线（Mock LLM 的测试直接判 Critical）。
