#### 启停延迟优化（healProfilesModuleFallback 增量重建）
排障中发现「initialize 240s 超时」并非死锁：`package/boot/app-boot/src/profile.ts` 的
`healProfilesModuleFallback` 每次 boot 都**全量 BFS** 重建 `$FF_HOME/profiles/node_modules` 闭包
（冷 ~60s、暖 ~5s），initialize 过早发出穿透等待窗口。已改**增量快照**：
- 闭包解析结果持久化到 `profiles/node_modules/.flowforge-fallback.json`；
- 后续 boot 经 `fallbackCacheFresh` 任一链接需通过：存在且为软链且 readlink 指向原 target、
  且 target `package.json` 的 mtime 与快照一致——三者全否则全量重建（迁移安装/升级/换位均能触发）；
- 校验只做逐链接 lstat/stat，**不重跑 BFS、不逐包 mkdir**。实测暖启动 **~5s → ~1.1s**，
  `packages/boot/app-boot/tests/profile.spec.ts` 14 用例全绿、oxlint 0 告警。
