# plan: P-544 打包图由构建图派生 + build 脚本解耦（hotfix）

> 实例：`p544-build-graph` ｜ 规格（Spec）：`docs/test/bugs/round13-browser-e2e-2026-09-19.md`（§P-544 缺陷单与其追查进展即本 hotfix 的规格与根因分析） ｜ 工作流：hotfix

**目标（Goal）**：让 `pnpm build` 能真正产出宿主产物（`lib/index.js`），解除 P-544 对 `pnpm start` 后端的阻断。
**架构（Architecture）**：**方案 B**——`tsdown.config.ts` 的 host face 打包范围改为**由 `tsconfig.host.json` 的 references 派生**，使打包图恒等于构建图（单一真相源，杜绝漂移）；client face 保持原 glob 不变（其 `entry: ''` 由包内配置决定，不受本缺陷影响）。另把 `build` 脚本解耦，使类型门禁不再以 `&&` 短路阻断产物生成。
**技术栈（Tech Stack）**：tsdown（workspace 模式）+ TypeScript project references + pnpm scripts。

## 全局约束
- **禁止假通过**：不得使用 `|| true`、`|| echo` 之类吞掉失败（BUG_PROTOCOL §六明列 S2）。
- 类型门禁不得削弱：`pnpm typecheck` 保持原样；CI 已在 `ts-ci.yml:51` 独立执行。
- client face 行为不变；不新增/删除包；不改 `tsconfig.host.json` 引用集。

## 任务清单

### 任务 1：打包图由构建图派生（方案 B）

- [ ] **步骤 1：`tsdown.config.ts` 增加派生函数**——读取 `tsconfig.host.json` 的 `references[].path`，规范化为目录（去 `./` 前缀、去尾部 `/tsconfig.host.json`），得到 host face 的 workspace 列表。

```ts
/** 打包图 = 构建图：host face 的 workspace 由 tsconfig.host.json references 派生。 */
function hostWorkspaceEntries(): string[] {
  const raw = readFileSync(new URL('./tsconfig.host.json', import.meta.url), 'utf8')
  const config = JSON.parse(raw) as { references?: { path: string }[] }
  return (config.references ?? [])
    .map((r) => r.path.replace(/^\.\//, '').replace(/\/tsconfig\.host\.json$/, ''))
}
```

- [ ] **步骤 2：host face 使用派生列表**——`workspace: client ? ['vendor/*', 'packages/*/*', 'apps/cli'] : hostWorkspaceEntries()`；client face 保持原样。

- [ ] **步骤 3：测试确认（先红后绿）**——红：改前 `npx tsdown --env.FF_BUILD_FACE host` 必报 `[@flowforge/integration-e2e] Cannot find entry`；绿：改后同一命令 exit 0 且 `packages/cats/routes/lib/index.js` 产出。此为本任务的对账断言测试（无新增 `tests/` 文件，验证以真实构建命令与产物存在性为准）。

```bash

ls packages/cats/routes/lib/index.js
```
