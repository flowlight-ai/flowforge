# 提示词模板创建规范（TEMPLATE.md）

> **用途**：在 `prompts/` 子目录中创建新提示词模板时，必须遵循本规范
> **依据**：`hiclaw/rules.md` + `flowforge/docs/design/naming-contract.md` v2.0
> **强制等级**：⛔ 违反即作废

---

## §1 模板编号规则

| CF | ContentForge 专用 | CF1-CF13 | CF-contentforge.md |

| V | LLM 审核方法论 | V1-V6 | LLM-review.md |

### 1.2 编号约束

- **唯一性**：同一前缀下编号必须唯一（已知的 P19、FF22/FF23 编号冲突需在新增时规避）
- **递增**：新增编号取当前最大值 +1
- **空缺保留**：若历史原因存在空缺（如 OR3），新增模板不填补空缺，从最大值 +1 开始

## §2 文件结构规范

### 2.1 文件命名

格式：`<前缀>-<项目名>.md`

示例：
- `P-common.md` — 公共模板
- `P-v7.md` — v7.0 增补模板
- `P-methodology.md` — v7.1 方法论模板
- `FF-flowforge.md` — FlowForge 专用模板
- `CF-contentforge.md` — ContentForge 专用模板
- `LLM-review.md` — LLM 审核方法论
- `Q-followup.md` — 追问纠偏模板

### 2.2 文件大小

- **单文件 ≤ 50 KB**：超出时需按子类别进一步拆分
- **顶层 prompts.md ≤ 50 KB**：仅作为索引，不重复模板内容

### 2.3 文件头部规范

每个文件必须包含以下头部：

```markdown
# <项目名> 模板（<前缀><起始编号>-<前缀><结束编号>）

> **本文件内容**：<一句话描述>
> **适用项目**：<项目名>
> **端口**：<端口号>
> **关键目录**：<项目目录路径>
```

## §3 模板格式规范

### 3.1 单个模板结构

```markdown
### <前缀><编号> <模板名称>

\```
<模板正文，使用代码块包裹以便复制>
\```
```

### 3.2 模板正文要求

1. **可执行性**：模板必须是用户可直接复制使用的完整提示词
2. **占位符规范**：使用 `{占位符}` 格式（如 `{项目名}`、`{模块名}`）
3. **禁止硬编码**：不引用具体文件路径、行数、密钥等
4. **铁律引用**：如涉及铁律，使用 `[rule:T1]` 或 `[rule:铁律3]` 格式

### 3.3 章节组织

按功能模块组织章节，使用三级标题：

```markdown
## X.1 <功能模块1>

### <前缀><编号1> <模板名1>

\```
<模板正文>
\```

### <前缀><编号2> <模板名2>

\```
<模板正文>
\```

## X.2 <功能模块2>
...
```

## §4 术语规范

### 4.1 官方名称优先

- **使用**：智能体、Evolvable Agent、可进化智能体、Forgekin、Spirit Agent
- **避免**：万物灵智体、炉灵、灵智系列（仅在社交场景使用，并需附官方名）

### 4.2 "万物"弱化

| 原说法 | 弱化为 |
|--------|--------|
| 万物可进化智能体 | 可进化智能体（Evolvable Agent） |
| 万物灵智体 | 多形态可进化智能体 |
| 养万物 | 锻造可进化智能体 |
| 万事万物 | 各类实体 |

### 4.3 12 核心概念命名

详见 `flowforge/docs/design/naming-contract.md` v2.0。

## §5 禁止内容

模板文件中**禁止**包含以下内容：

1. ❌ 修改记录表（如 `| 日期 | 版本 | 修改内容 |`）
2. ❌ 版本变迁说明（如 `v2.0→v2.1→v2.2 变更说明`）
3. ❌ 开发过程反思（应放到 `rules.md` 第十二部分）
4. ❌ 用户原话引用（如 `用户说xxx`）
5. ❌ 具体文件行数引用（如 `1154行/945行`）
6. ❌ 项目过程时间线（如 `第一阶段/第二阶段`）
7. ❌ 全角标点（如 `？`、`：`，应使用半角 `?`、`:`）
8. ❌ "待补充"占位符

---

## §6 允许内容

模板文件中**允许**包含以下内容：

1. ✅ 模板正文（用户可直接复制的提示词）
2. ✅ 使用说明（如何使用该模板）
3. ✅ 适用场景清单（项目维度的检查清单）
4. ✅ 实现要点（参考实现的要点总结）
5. ✅ 跨项目适配清单（表格形式）
6. ✅ 铁律引用（如 `[rule:T7]`）
7. ✅ 其他模板的交叉引用（如 `[prompt:P8A]`）

---

## §7 新增模板流程

1. **确定编号**：取当前前缀最大编号 +1
2. **选择文件**：根据模板归属选择对应文件
3. **检查大小**：若新增后超出 50KB，需进一步拆分
4. **编写模板**：按 §3 规范编写
5. **更新索引**：在 `README.md` 中更新模板范围
6. **更新顶层**：在 `prompts.md`（顶层）的索引中更新引用
7. **术语审查**：用 Grep 检查"万物"、"全角标点"等禁止内容
8. **完整性验证**：确保模板可独立执行，不依赖外部未引用资源

## §8 模板示例

### 8.1 简单模板示例

```markdown

\```

□ 场景1：xxx
□ 场景2：xxx
\```
```

## §10 审查清单

新增模板前，逐项检查：

- [ ] 编号是否唯一（同前缀下）
- [ ] 文件大小是否 ≤ 50KB
- [ ] 文件头部是否完整（4 个字段）
- [ ] 模板正文是否使用代码块包裹
- [ ] 是否使用半角标点
- [ ] 是否弱化"万物"说法
- [ ] 是否使用官方 AI 术语
- [ ] 是否无过程记录、修改记录、版本变迁说明
- [ ] 是否无"待补充"占位符
- [ ] 是否更新了 `README.md` 索引
- [ ] 是否更新了顶层 `prompts.md` 索引
