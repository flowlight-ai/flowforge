## 二、红线详解

### 红线 1：禁止添加 CoT 检测/中文比例检测

**禁止做法**：
- ❌ 检测 LLM 输出中是否包含 `<think>` 标签
- ❌ 检测 LLM 输出中中文字符占比
- ❌ 用正则匹配 CoT 痕迹作为质量分维度

**原因**：CoT 检测容易被绕过，且干扰正常推理流程；中文比例检测对多语言场景不友好。

### 红线 2：质量分阈值默认 0.85

**配置**：
- 默认值：0.85
- 可在 Loop 配置中覆盖（如选题 Loop 用 0.80）
- v4.0 从 0.9 调整为 0.85，平衡质量与可用性

**禁止做法**：
- ❌ 在代码中硬编码 0.9 等其他阈值
- ❌ 通过修改提示词引导评委给高分来"达成"阈值

### 红线 3：禁止使用 Mock LLM

详见 [doc:rules/test-iron-rules.md#t1]。

### 红线 4：禁止使用假数据

详见 [doc:rules/test-iron-rules.md#t2]。

### 红线 5：禁止跳过验证

详见 [doc:rules/test-iron-rules.md#t3]。

### 红线 6：禁止只看退出码不检查输出质量

**禁止做法**：
- ❌ `assert process.returncode == 0` 后不检查 stdout 内容
- ❌ `assert response.status_code == 200` 后不检查 response.json() 内容

**正确做法**：
- ✅ 检查退出码 + 检查输出内容质量（结合 T6 指标采集 + T7 LLM 审核）

### 红线 7：禁止在修复问题时修改不相关代码

**铁律**：修复 Bug 时只修改目标问题相关代码，禁止"顺手"重构、修改不相关代码。

**禁止做法**：
- ❌ 修复 A Bug 时顺手重命名 B 模块的变量
- ❌ 修复 A Bug 时顺手删除 C 模块的注释
- ❌ 修复 A Bug 时顺手"优化"D 模块的实现

### 红线 8：禁止删除已有测试用例

**铁律**：已有测试用例必须保留，即使暂时失败也必须修复而非删除。

**例外**：仅当测试用例本身错误（如断言了错误行为）才可删除，且必须在 PR 中说明原因。

### 红线 9：禁止用继承替代组合/插件

**禁止做法**：
- ❌ `class ContentForgeAgent(BaseAgent)` — 用继承扩展业务能力
- ❌ `class BaseNovelAgent(BaseAgent)` — 创建业务基类

**正确做法**：
- ✅ 通过 Plugin 协议注册业务能力
- ✅ 通过组合（Composition）注入依赖
- ✅ 通过 YAML 配置声明 Agent

### 红线 10：禁止在 flowforge 中写死业务领域代码

**铁律**：FlowForge 是纯通用框架，禁止包含任何业务领域代码。

**禁止做法**：
- ❌ 在 flowforge 中写"内容创作"相关代码
- ❌ 在 flowforge 中写"股票分析"相关代码
- ❌ 在 flowforge 中写"小说创作"相关代码

**正确做法**：
- ✅ 业务领域代码放 *Forge 项目（config/web/app/plugins.py）
- ✅ 通用能力下沉到 flowforge（至少 2 个上层应用需要）

### 红线 11：禁止硬编码提示词/路径/密钥/端口

**禁止做法**：
- ❌ 在 .py 文件中写 `prompt = "你是一个写作助手..."`
- ❌ 在 .py 文件中写 `path = "/home/hyg/ai/openclaw/..."`
- ❌ 在 .py 文件中写 `api_key = "sk-xxx"`
- ❌ 在 .py 文件中写 `port = 8000`

**正确做法**：
- ✅ 提示词外置到 YAML 配置（`config/prompts/*.yaml`）
- ✅ 路径通过配置系统注入（`config/system.yaml`）
- ✅ 密钥通过 `.env` 注入
- ✅ 端口通过配置文件或环境变量

### 红线 12：禁止绕过 DI 容器直接实例化

**禁止做法**：
- ❌ `from workers.topic_agent import TopicAgent; agent = TopicAgent()`
- ❌ 在业务代码中 `LLMClient()` 直接实例化

**正确做法**：
- ✅ 所有依赖通过构造函数注入
- ✅ 由 DI 容器管理生命周期
- ✅ 通过 `sdk.xxx` 访问框架能力

### 红线 13：禁止直接操作数据库

**禁止做法**：
- ❌ `cursor.execute("INSERT INTO tasks ...")`
- ❌ `db.session.query(Task).filter(...)`
- ❌ 在 Agent / Tool 中直接 import SQLAlchemy

**正确做法**：
- ✅ 所有数据库操作通过 Repository 层
- ✅ Repository 由 DI 容器注入到 Agent

### 红线 14：禁止不按 prompts.md 和 rules.md 执行

**铁律**：所有 AI 助手开发必须严格遵守 `hiclaw/prompts.md` 和 `hiclaw/rules/` 子目录下所有规范。

**冲突优先级**：
1. 用户最新指令（最高）
2. prompts.md
3. 项目 docs/
4. rules.md（本索引）+ rules/ 子目录
5. archive/ 历史文档

### 红线 15：禁止偷工减料（发现未实现即 Bug）

详见 [doc:rules/test-iron-rules.md#t5]。
